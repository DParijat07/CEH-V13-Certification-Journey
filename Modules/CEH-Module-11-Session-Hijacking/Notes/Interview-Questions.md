# Interview Questions

## CEH Module 11 – Session Hijacking

---

# Basic Level Questions

### 1. What is Session Hijacking?

**Answer:**

Session Hijacking is an attack in which an attacker takes control of a legitimate user's authenticated session by stealing or manipulating the session identifier (such as a session cookie or token), allowing unauthorized access without knowing the user's password.

---

### 2. Why do web applications use sessions?

**Answer:**

HTTP is a stateless protocol. Sessions allow web applications to remember authenticated users across multiple HTTP requests.

---

### 3. What is a Session ID?

**Answer:**

A Session ID is a unique identifier generated by the server after successful authentication to identify a user's active session.

---

### 4. What is a cookie?

**Answer:**

A cookie is a small piece of data stored by the browser that helps maintain session information, user preferences, and authentication state.

---

### 5. Name some common session cookie names.

**Answer:**

- PHPSESSID
- JSESSIONID
- ASP.NET_SessionId
- sessionid (Django)
- connect.sid (Node.js)

---

### 6. What is the difference between Authentication and Authorization?

**Authentication**

Verifies the user's identity.

**Authorization**

Determines what resources the authenticated user is allowed to access.

---

### 7. What is a Session Token?

**Answer:**

A Session Token is an authentication credential used to maintain a user's authenticated session. It may be stored in cookies or HTTP headers.

---

### 8. What is JWT?

**Answer:**

JWT (JSON Web Token) is a compact, digitally signed token commonly used for authentication in modern web applications and APIs.

---

### 9. Why is HTTP considered stateless?

**Answer:**

Because each HTTP request is processed independently without remembering previous requests.

---

### 10. What happens after a successful login?

**Answer:**

- User credentials are verified.
- Server creates a session.
- A Session ID or Token is generated.
- The Session ID is sent to the browser.
- The browser sends it with future requests.

---

# Intermediate Level Questions

### 11. What is Session Sidejacking?

**Answer:**

Capturing session cookies over an insecure network (typically HTTP) to impersonate a legitimate user.

---

### 12. What is Session Fixation?

**Answer:**

An attacker forces the victim to use a Session ID chosen by the attacker before authentication.

---

### 13. What is Session Replay?

**Answer:**

The attacker captures a valid authentication token or session identifier and reuses it later to gain unauthorized access.

---

### 14. What is Cookie Theft?

**Answer:**

Stealing session cookies from the victim's browser using XSS, malware, malicious extensions, or physical access.

---

### 15. What is the Secure cookie attribute?

**Answer:**

It ensures cookies are transmitted only over HTTPS connections.

---

### 16. What is HttpOnly?

**Answer:**

It prevents client-side JavaScript from accessing cookies, reducing the risk of cookie theft through XSS.

---

### 17. What is SameSite?

**Answer:**

A cookie attribute that helps mitigate Cross-Site Request Forgery (CSRF) attacks.

Values:

- Strict
- Lax
- None

---

### 18. Why should Session IDs be regenerated after login?

**Answer:**

To prevent Session Fixation attacks.

---

### 19. What is HSTS?

**Answer:**

HTTP Strict Transport Security forces browsers to use HTTPS for future requests.

---

### 20. Why is HTTPS important?

**Answer:**

HTTPS encrypts communication, protecting session cookies, authentication tokens, and sensitive data from interception.

# SOC Analyst Questions

### 31. How would you detect Session Hijacking?

**Answer:**

Monitor:

- Authentication logs
- Web server logs
- Session reuse
- Impossible travel
- User-Agent changes
- Multiple IP addresses
- Concurrent sessions

---

### 32. What is Impossible Travel?

**Answer:**

A user appears to authenticate from geographically distant locations within an unrealistic timeframe.

---

### 33. Which logs are most useful?

**Answer:**

- Authentication Logs
- Apache/Nginx Logs
- Firewall Logs
- VPN Logs
- SIEM Alerts
- EDR Logs

---

### 34. Which MITRE ATT&CK technique maps directly to Session Hijacking?

**Answer:**

**T1539 – Steal Web Session Cookie**

---

### 35. Which SIEM tools are commonly used?

**Answer:**

- Splunk
- Microsoft Sentinel
- Elastic Security
- IBM QRadar

# Scenario-Based Questions

### 36. A user logs in from India and five minutes later from Germany using the same Session ID. What would you investigate?

**Answer:**

- Impossible travel
- Session hijacking
- VPN usage
- Device information
- Authentication logs
- User-Agent changes

---

### 37. A cookie lacks the Secure attribute. What is the risk?

**Answer:**

The cookie may be transmitted over HTTP and intercepted by attackers.

---

### 38. Why should cookies have the HttpOnly attribute?

**Answer:**

To prevent JavaScript from reading session cookies during XSS attacks.

---

### 39. What happens if the server doesn't invalidate sessions after logout?

**Answer:**

An attacker with the stolen session cookie may continue using the session.

---

### 40. How would you respond to a confirmed session hijacking incident?

**Answer:**

- Terminate active sessions
- Revoke session tokens
- Reset user password
- Enable MFA
- Block malicious IPs if appropriate
- Review logs
- Notify the user
- Document the incident
