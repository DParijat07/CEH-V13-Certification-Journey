# CEH v13 – Module 11: Session Hijacking (Complete Notes)

# Introduction

Session Hijacking is an attack where an attacker gains unauthorized access to a user's authenticated session by stealing or manipulating the session identifier (Session ID, Cookie, or Authentication Token).

Instead of stealing the user's credentials, the attacker steals the session itself.

Since the web uses the HTTP protocol, which is **stateless**, web applications use sessions to remember authenticated users.

# HTTP Session

HTTP is a **stateless protocol**.

Every request sent to the server is independent.

Example:

```
Request 1 → Login

Request 2 → Open Dashboard

Request 3 → Profile

Request 4 → Logout
```

Without sessions, the server would ask the user to login every time.

Therefore,

**Authentication → Session Creation → Session ID → User Identification**

---

# Session Lifecycle

```
User Login

↓

Server validates credentials

↓

Session Created

↓

Unique Session ID Generated

↓

Session Cookie Sent

↓

Browser Stores Cookie

↓

Browser sends Cookie in every request

↓

Server validates Session

↓

User gets access

↓

Logout / Timeout

↓

Session Destroyed
```

# Session ID

A Session ID is a unique random value generated by the web server.

Example

```
PHPSESSID=f6g98h3jsl29ad1
```

or

```
JSESSIONID=84A72931BC21A
```

or

```
ASP.NET_SessionId=AJD732KD91
```

The Session ID identifies an authenticated user.

# Cookies

# Session Hijacking

Session Hijacking is stealing an authenticated user's session.

Goal:

```
User logs in

↓

Attacker steals Session Cookie

↓

Attacker sends Cookie

↓

Server believes attacker is legitimate user
```

---

# Types of Session Hijacking

## 1. Session Sniffing

Attacker captures network traffic.

Requirements

- Unencrypted HTTP
- Shared Network

Tools

- Wireshark
- tcpdump

---

## 2. Session Sidejacking

Intercepting session cookies transmitted over HTTP.

Usually performed on open Wi-Fi.

Prevention

- HTTPS
- Secure Cookies

---

## 3. Session Fixation

Instead of stealing a session,

the attacker forces the victim to use a Session ID chosen by the attacker.

Steps

```
Attacker creates Session

↓

Gets Session ID

↓

Sends link to victim

↓

Victim logs in

↓

Server associates attacker's Session ID

↓

Attacker reuses Session
```

---

## 4. Cookie Theft

Methods

- XSS
- Malware
- Browser extensions
- Physical access

---

## 5. Cross Site Scripting (XSS)

JavaScript steals cookies.

Example

```
document.cookie
```

Can send cookies to attacker's server.

---

## 6. Man in the Middle (MITM)

Attacker positions themselves between client and server.

Captures

- Cookies
- Credentials
- Tokens

---

## 7. Session Replay

Previously captured authentication tokens are replayed.

Common against APIs.

# CEH Exam Tips

Remember:

- HTTP is stateless.
- Sessions maintain authentication.
- Cookies usually store Session IDs.
- XSS can steal cookies.
- HTTPS protects cookies in transit.
- HttpOnly protects against JavaScript access.
- SameSite helps prevent CSRF.
- Session Fixation uses an attacker-controlled Session ID.
- Session Sidejacking intercepts cookies over insecure networks.

---

# Key Takeaways

- Session Hijacking targets authenticated sessions rather than passwords.
- Secure session management is essential for protecting web applications.
- Burp Suite and browser developer tools are fundamental for testing session security.
- Defensive controls such as HTTPS, Secure cookies, HttpOnly, SameSite, and MFA significantly reduce the risk of session hijacking.
- Monitoring session anomalies and authentication logs is critical for SOC analysts to detect and respond to session hijacking attempts.
